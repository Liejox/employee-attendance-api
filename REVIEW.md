# REVIEW.md

Defects found in the starter `app/main.py` (line numbers refer to the starter as shipped). Every row was reproduced or tested before it was fixed. Rules R1-R10 are the ones in `openapi.yaml`.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes`, l.35 | `punch_in.replace(hour=h, minute=m)` builds the shift start on the punch-in's own date and time zone. Punch-ins are UTC instants but shifts are IST, so the shift start is 5.5 h off; overnight shifts (22:00-06:00) get the wrong day. | Employee with shift 22:00-06:00 punching in at 01:05 IST: starter returns 0, correct is 185 (R1/R2). | `shift_bounds(date, start, end)` builds the start in IST on the attendance date and moves an overnight end to the next day. |
| 2 | `compute_late_minutes`, l.36-37 | `int(seconds / 60)` truncates to whole minutes *before* the grace check `> 10`. 09:40:01 gives 10 minutes, and `10 > 10` is false, so a late punch-in counts as on time. | Shift 09:30, punch-in 09:40:01: starter 0, correct 10. 10:15:59 must give 45. | Compare seconds `> 600` (strictly more than 10:00), then take the floor of minutes since `shift_start`. |
| 3 | `compute_late_minutes` / all helpers | Seconds are never truncated (R1). 09:40:00.900 is treated as later than 09:40:00. | Punch-in 09:40:00.900: should be 0. | `trunc_seconds()` is applied to every instant before any calculation and the truncated value is stored. |
| 4 | `compute_work_hours`, l.41 | Python `round()` on a float is banker's rounding on a binary value, not half-up (R4). | 450 s = 0.125 h: starter 0.12, correct 0.13. | `Decimal(seconds) / 3600` with `ROUND_HALF_UP`. |
| 5 | `compute_overtime`, l.47 | No 30-minute threshold (R3): any positive minutes are reported as overtime. | Punch-out 18:50 with shift end 18:30: starter 20, correct 0. | Floor minutes, return them only if `>= 30`, else 0. |
| 6 | `compute_overtime`, l.46 | Shift end is always on the punch date, so an overnight shift's end (next day) is wrong. | 7 | helpers (missing) | There is no half-day rule at all (R5), so `half_day` is always false. | Work 4 h 29 m 59 s rounds to 4.50 and is NOT a half day; 4.48 h is. | `compute_half_day` on the *rounded* work_hours (`< 4.50`). |
| 8 | module top, l.22 | `MongoClient` is not `tz_aware`, so stored UTC datetimes come back naive and are mixed with local times. | 9 | whole app | No indexes at all: no uniqueness guarantee for `emp_code` or `(emp_code, date)`, every query is a collection scan. | Duplicate employees / attendance rows under concurrency; `COLLSCAN` in explain. | `ensure_indexes()` runs at startup (lifespan), see DECISIONS.md. |
| 10 | `health`, l.72 | Always answers `ok`, even if MongoDB is down. | Stop Atlas / break the URI: `/health` still says ok. | `ping` the database; return 503 if it fails. |
| 11 | `create_employee`, l.79-80 | Check-then-insert race: two parallel POSTs both pass `find_one` and both insert. | Fire the same POST twice at once: two 201s, duplicate `emp_code`. | Unique index on `emp_code`; `DuplicateKeyError` becomes 409. |
| 12 | `EmployeeIn`, l.53-60 | No validation. Empty names, bad e-mail, `shift_start="25:99"`, `joined_on="2026-02-30"`, equal shift start/end all accepted. | POST with those values returns 201. | Field patterns/lengths, real-date check for `joined_on`, shifts must differ, all give 422. |
| 13 | `create_employee`, l.82 | `created_at = datetime.now()` is a naive local time and is returned as a datetime instead of epoch ms. | Value depends on the server's time zone. | Stored as UTC; returned through `employee_out` as epoch ms. |

| 15 | `list_employees`, l.94 | `total` is `count_documents({})`, ignoring the department filter (R10). | `?department=Sales`: total counts everyone. | `count_documents(q)` with the same filter. |

| 17 | `punch_in`, l.101-113 | Unknown `emp_code`: `find_one` returns `None`, then `emp["shift_start"]` raises, so 500 instead of 404. | `{"emp_code": "EMP9999"}`. | Explicit 404. |

| 27 | missing endpoints | `punch-out`, `PATCH /attendance/{emp_code}/{date}`, the four analytics endpoints and `/admin/explain` do not exist. | `404` on all of them. | Implemented. Punch-out and PATCH use conditional `find_one_and_update` so a concurrent request gets 409 instead of overwriting. |

## Looked at and decided it is NOT a defect

* **`date` stored as a `YYYY-MM-DD` string.** ISO dates sort lexicographically, so `$gte` / `$lte` range queries and index range scans on the string are correct. Kept as is.
* **`IST = timezone(timedelta(hours=5, minutes=30))`.** Correct for the required zone (no DST in India).
* **`history: []` and `overtime_minutes: 0` on a new punch-in.** Correct: punch-in never writes history and overtime is only known at punch-out.
* **`load_dotenv()` and the `MONGO_URI` / `MONGO_DB` environment variables.** Fine for local use; no secret is in the code.
* **Storing `punch_in` / `punch_out` as BSON dates.** Correct; only the API converts them to epoch ms.
* **`409` for a second punch-in on the same date.** Matches the contract; I only changed *how* it is detected (unique index instead of a read).
